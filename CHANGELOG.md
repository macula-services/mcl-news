# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.3.0 - 2026-10-30

- **The base library is macula 18** (macula-io/macula#147, mcl-om#41): the macula
  floor moves `~> 16.0` to `~> 18.0` and `mcl_om` `~> 1.4` to `~> 1.6`. 18 keeps
  wire 1.0, so this service still speaks to every wire 1.0 box; what it adds is
  the caller class a handler-bearing capability must name and the source rule a
  subscription must name, both of which mcl_om 1.6 refuses the boot over. This
  service declares neither — `capabilities/0` is `[]` and there is no
  `subscriptions/0` — so the rule asks nothing of it and no reach changes.
- **The revocation bound from macula 16 is part of this base** (macula#118,
  carried since the 16 floor and left Unreleased until now): an endorsement
  admits its holder for at most 24 hours, and a gated overlay context must pass
  `member_standing`. This service gates no overlay and issues no endorsement.

## [0.2.0] - 2026-10-17

- **Wire 1.0: on macula 15.6 and mcl_om 1.0** (macula-fleet#27). macula 15 neither reads a 14 node's frames nor completes a handshake with it, so the fleet moves across in one flag day rather than node by node. mcl_om 1.0 is this service on the new wire: no function it calls moved or changed arity. `mcl_om ~> 0.x` takes any 0.x, so a 0.43 on macula 15 would have rolled the live 0.10.3 fleet on its next build; it names 1.0, which is outside that range.

## [0.1.1] - 2026-10-15

- **Rebuilt on mcl_om 0.42** (mcl-om#26): advertisement renewals move to a 70 s interval under a 280 s TTL (from 30 s / 120 s), so a station sends far fewer renewal frames; the health windows derive from the interval. Carries macula 14.11.0 (mcl_om 0.42's floor).

## [0.1.0] - 2026-10-15

### Changed

- The wire is named, not inherited: `mcl_om ~> 0.39` with `macula ~> 14.2`, the
  line mcl-echo, mcl-rag, mcl-stations, mcl-graph, mcl-tube, mcl-mail and
  mcl-citizens carry. `mcl_om ~> 0.28` was a two-part tilde and so floated to
  whichever 0.x was newest; today that is 0.40.0 on macula 14, which is the
  wire the fleet runs, but the next mcl_om may reach for macula 15, the
  wire-1.0 island the live stations do not speak before 16 Oct. Named, the two
  constraints clash at resolve time instead of moving this service onto wire
  1.0 unnoticed.
- mcl_om: the service answers `mcl-news/info`
  with no code of its own, which also makes it count as online on the realm's
  Providers desk, and a failed publish announcement can no longer kill it.
- Built in `macula-ci-otp` and run on `macula-pq-runtime`, the team's image
  pair pinned by dated tag and digest, instead of the hexpm builder and a
  floating `alpine:3.22` runtime. The image is labelled with the commit it
  was built from.

### Added

- The scaffold, generated by `rebar3 new mcl_service`: an OTP release that
  boots on `mcl_om`, joins the mesh, and answers `/health` on 8498.
- The news sensor, ported from `hecate-news`: polls sovereign RSS/Atom
  sources, enriches each item deterministically, and reports every new one as
  `news_item_reported_v1`.
- The start refuses a `MCL_REALM_NAME` whose sha256 is not `MCL_REALM`.
- `rebar3 dialyzer` in CI, with macula in the PLT.
- mcl_om brings no barrel_docdb and so no rocksdb: the
  image and CI install no cmake and no rocksdb codec libraries.
- The boot claim is labelled for the realm's operator: `MCL_SERVICE_NAME`
  (`mcl-news`) and `MCL_BOX`, the host that deploys it.

### Changed from hecate-news

- One canonical app fact, `<realm>/mcl-news/news/wire/news_item_reported_v1`,
  instead of `<society>/feed` plus one sub-topic per source type, country and
  topic class. The per-slice fan-out was dropped: it existed so each society
  mind could subscribe to a slice, no consumer of it exists, and values belong
  in the payload. Category, country and source type are payload fields.
- Every string in the fact is tagged text; hecate-news sent bare binaries,
  which consumers outside the BEAM received as hex.
- The fact carries no `from` label and no `type`: the verified publisher is
  the sender, and the topic is the kind.
- No record-only `news.report_item` capability: the sensor offers no
  procedure.
- Configuration is `MCL_NEWS_*` and `MCL_REALM_NAME`; `HECATE_SOCIETY` is gone,
  the realm replaces the society namespace. `MCL_NEWS_POLL_MS`,
  `MCL_NEWS_SEED_COUNT` and `MCL_NEWS_MAX_SEEN` must be positive; zero or junk
  falls back to the default.
- An item is marked seen only once its report succeeded (the publish is
  synchronous), so a dark mesh at boot or later delays a report instead of
  losing it; the first poll no longer waits on the mesh.
- Each source is primed on its own first successful fetch, so a source that
  was down at boot seeds when it returns instead of reporting its backlog.
- A source that answers but yields no items is logged.
- The og:image page head is cut on a UTF-8 character boundary, so a cut
  mid-character no longer loses the picture.
- The sensor's seeding and dedupe have tests; a feed declaring an entity is
  pinned as refused whole.
- `docs/INTEGRATION.md` and `deploy/.env.example` are not carried over: they
  described the society feed, the service certificate and mind wiring, which
  are gone. The README and `deploy/docker-compose.yml` carry what applies.
- `Containerfile` building an alpine image, with macula's QUIC NIF compiled from
  source rather than fetched against a foreign libc.
- `deploy/docker-compose.yml`, the service's own run contract.
- CI: `lint-and-test` on pushes to `main` and on pull requests, `build-and-push` to
  the registry: `:main` and `:<sha>` on `main`, which nothing follows; `:<semver>`
  on a `v*` tag, promoted to `:latest` once signed and attested.
